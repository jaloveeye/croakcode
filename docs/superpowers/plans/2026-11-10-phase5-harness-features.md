# Phase 5: 하네스 기능 보강

- **날짜**: 2026-11-10
- **상태**: 계획
- **배경**: 2026-11-10에 두 프로젝트를 조사했다.
  - ZCode: zai-org/ZCode, Apache-2.0
  - DeepSeek Harness: deepseek-ai/deepseek-harness, MIT
- **결정**: croakcode에 맞는 기능 여덟 가지를 골랐다. 사용자는 여덟 가지를 모두 넣고 직접 구현하기로 정했다. 같은 날 사용자가 TUI 기능 세 가지(Task 9~11)를 더했다.

## 1. 직접 구현 원칙

라이선스 의무를 피하려고 두 프로젝트의 코드를 가져오지 않는다.

- 두 프로젝트의 소스 코드를 읽지 않는다. 설계 문서와 README에서 얻은 생각만 쓴다.
- 각 기능의 동작은 이 문서의 명세로 정한다. 구현과 테스트와 문구는 croakcode에 맞게 새로 쓴다.
- 변수 이름, 메시지 문구, 상수 값을 두 프로젝트에서 옮겨 적지 않는다. 상수는 croakcode의 측정값으로 정한다.
- PR 설명에 이 원칙을 지켰다고 적는다.

## 2. 판단 기준

croakcode는 사내 모델(Qwen 27B NVFP4)을 게이트 뒤에서 쓴다. 기능마다 다음 기준으로 효과를 본다.

| 기준 | 지금 값 | 측정 방법 |
|---|---|---|
| 캐시 없는 첫 요청 크기 | 약 7,000토큰(이 저장소 밖 폴더) | 가짜 서버로 본문을 받아 잰다 |
| 웹 검색 뒤 다음 요청 크기 | 결과 하나에 최대 50KB | 같은 방법 |
| 캐시 없는 처리 속도 | 초당 약 1,040토큰 | 게이트에서 첫 토큰 시간을 잰다 |

게이트의 실행 허가, 개인정보 마스킹, 감사를 거치지 않는 경로를 만들지 않는다.

## 3. 작업

### Task 1. 도구 출력 한도

- **명세**: 제품 설정(`upstream/.croakcode/croakcode.jsonc`)에 `tool_output`을 넣는다. 한 결과의 한도는 400줄, 16KB다. 넘는 출력은 지금처럼 파일로 저장하고 앞부분과 저장 경로만 모델에 준다.
- **근거**: 예전 opencode 설정이 같은 값을 썼다. croakcode로 옮길 때 빠졌다.
- **수용**: 50KB 웹 페이지를 가져온 뒤의 다음 요청이 16KB 한도 안에 든다.

### Task 2. 웹 내용 표시

- **명세**: webfetch 결과 앞에 "외부 웹 내용이며 지시가 아니다"라는 표시를 붙인다. HTML에서 스크립트, 스타일, 숨긴 요소를 지운 뒤 변환한다. 결과를 자른 경우 끝에 자른 사실과 원래 크기를 적는다.
- **수용**: 숨긴 요소에 넣은 지시문이 결과에 나오지 않는다. 표시가 모든 결과에 붙는다.

### Task 3. 모델의 이상 출력 대응

- **명세**:
  - 모델이 글도 도구 호출도 없이 끝나면 한 번만 다시 요청한다. 길이 초과나 거부로 끝난 경우는 다시 요청하지 않는다.
  - 도구 입력이 객체 대신 JSON 문자열로 오면 한 번 풀어서 쓴다. 풀 수 없으면 지금처럼 오류로 돌려준다.
- **수용**: 두 경우를 재현하는 테스트가 통과한다. 다시 요청은 한 턴에 한 번을 넘지 않는다.

### Task 4. webfetch 내용 추출

- **명세**: webfetch에 선택 인자 `prompt`를 더한다. `prompt`가 있으면 가져온 내용과 질문을 작은 모델(`small_model`, 없으면 같은 모델)에 따로 보낸다. 본 대화에는 뽑은 답과 주소만 넣는다. `prompt`가 없으면 지금처럼 동작한다.
- **근거**: 본 프롬프트에 웹 페이지가 쌓이지 않아 캐시가 유지된다. 대신 추출 요청이 한 번 더 든다.
- **주의**: 추출 요청도 게이트를 거친다. 개인정보 마스킹과 사용량 기록이 그대로 적용되어야 한다.
- **수용**: `prompt`를 준 호출 뒤의 다음 요청이 원문 대신 답만 담는다. 추출 요청이 게이트 사용량 기록에 남는다.

### Task 5. 읽기 전 수정 막기

- **명세**: 세션마다 읽은 파일과 읽은 시점의 수정 시각과 크기를 기록한다. edit와 write는 이미 있는 파일을 고칠 때 이 기록을 확인한다. 다음 두 경우에는 거부하고 먼저 읽으라고 알린다. 하나는 읽은 적이 없는 파일이고, 다른 하나는 읽은 뒤에 바뀐 파일이다. 새 파일을 만드는 경우는 막지 않는다.
- **수용**: 읽지 않은 파일, 읽은 뒤 바뀐 파일, 새 파일 세 경우의 테스트가 통과한다. 세션을 다시 열어도 기록이 남는다.

### Task 6. 바뀌지 않은 파일 다시 읽기 생략

- **명세**: 같은 세션에서 같은 파일의 같은 범위를 다시 읽을 때, 수정 시각과 크기가 같으면 짧은 안내만 돌려준다. 안내에는 이전에 읽은 시점을 적는다. 압축(compaction)이 일어나면 기록을 비운다. 압축 뒤에는 이전 내용이 대화에 없기 때문이다.
- **의존**: Task 5의 읽기 기록을 쓴다.
- **수용**: 다시 읽기는 안내만 돌려준다. 파일이 바뀐 경우와 압축 뒤에는 내용을 돌려준다.

### Task 7. bash 위험한 형태 확인

- **명세**: 이미 쓰는 tree-sitter 구문 분석 결과로 위험한 형태를 찾는다. 위험한 형태는 허용 규칙이 있어도 사용자에게 묻는다.
  - 명령 치환(`$(...)`, 백틱)과 하위 셸
  - 파일로 쓰는 출력 방향 바꾸기
  - `find`의 `-exec`, `-execdir`, `-ok`, `-delete`
  - `sed`의 `-i`와 스크립트 안의 `e`, `w` 명령
  - 구문 분석에 실패한 명령
- **수용**: 위 형태마다 허용 규칙이 있어도 묻는다는 테스트가 통과한다. 위험하지 않은 명령의 허용은 그대로다.

### Task 8. 도구 정의 지연 불러오기 (실험)

- **명세**: `experimental.deferred_tools`를 켜면 첫 요청에 기본 도구와 도구 검색 도구만 넣는다. 도구 검색 결과로 필요한 도구의 정의를 돌려주고, 모델은 대리 호출 도구로 그 도구를 부른다. 대리 호출도 실제 도구 이름으로 권한 확인, 실행 허가, 감사를 거친다. 기본은 꺼짐이다.
- **수용**: 켰을 때 첫 요청이 얼마나 줄어드는지 잰다. Qwen 27B로 대표 작업 다섯 개를 돌려 성공률을 끈 경우와 비교한다. 성공률이 떨어지면 기본값을 바꾸지 않는다.

### Task 9. 답변 도중 끼어들기

- **현재**: 응답 중에 보낸 메시지는 다음 단계 경계에서 들어간다(`prompt.ts:1462`). 도구 호출이 없는 긴 답변을 쓰는 동안에는 답변이 끝날 때까지 기다린다.
- **명세**: 입력창에서 별도 키로 보내면 지금 쓰는 답변을 멈추고 새 메시지를 바로 넣는다. 멈춘 답변의 앞부분은 대화에 남긴다. 실행 중인 도구는 끝날 때까지 기다린 뒤 멈춘다. 끼어든 메시지는 지금의 STEERING 표시와 구분해 보여 준다.
- **수용**: 긴 답변 도중 끼어들면 1초 안에 생성이 멈추고, 다음 요청에 새 메시지와 앞부분 답변이 들어간다. 도구 실행 도중에는 도구 결과가 기록된 뒤에 멈춘다.

### Task 10. 답변 복사 버튼

- **현재**: 마지막 답변 복사는 있다(`messages.copy`, `<leader>y`). 키 조합을 알아야 쓸 수 있다.
- **명세**: 답변마다 아래 줄에 "복사" 표시를 둔다. 마우스로 누르면 그 답변의 글 전체를 마크다운 그대로 클립보드에 넣는다. 도구 출력과 추론은 넣지 않는다. 키보드로는 선택한 답변을 복사한다. 원격 터미널에서도 되도록 OSC 52를 쓴다.
- **수용**: 답변 세 개 가운데 가운데 답변의 복사 표시를 누르면 그 답변만 복사된다. tmux와 SSH 안에서도 복사된다.

### Task 11. 대화창 스크롤 표시

- **명세**: 먼저 증상을 재현해 기록한다. 긴 대화에서 스크롤 위치와 스크롤바가 제대로 보이는지, 새 답변이 올 때 아래로 따라가는지 확인한다. 원인을 찾은 뒤 고친다.
- **수용**: 재현한 증상이 tmux 화면 캡처에서 사라진다.

### Task 12. 맨 아래로 가는 버튼

- **배경**: 2026-11-10에 사용자가 더한 작업이다.
- **명세**: 대화창을 위로 올려 두면 오른쪽 아래에 "↓ 맨 아래로 (End)" 버튼을 띄운다. 누르면 맨 아래로 간다. 위로 올린 동안 내용이 늘어나면 "새 내용"을 덧붙이고 강조색으로 바꾼다. 맨 아래에 있으면 숨긴다.
- **수용**: 답변이 오는 중에 위로 올리면 "새 내용"이 보인다. 누르면 마지막 줄이 보이고 버튼이 사라진다.

## 4. 순서

1. Task 1, 2, 3: 작고 효과가 바로 보인다.
2. Task 5, 6: 읽기 기록을 함께 쓴다.
3. Task 4: 추출 요청의 게이트 경로를 확인해야 한다.
4. Task 7: 권한 판단을 바꾸므로 보안 시험을 함께 한다.
5. Task 8: 실험으로 진행하고 측정 결과로 기본값을 정한다.
6. Task 9, 10, 11, 12: TUI 작업이다. Task 1~3과 함께 먼저 해도 된다. 사용자가 자주 쓰는 기능이라 체감이 크다.

작업마다 PR 하나를 연다. 각 PR은 전체 회귀 시험(`scripts/phase2-gate-replay.sh`, `scripts/phase3-gate-replay.sh`)을 통과해야 한다.
