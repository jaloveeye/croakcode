# 첫 요청 지연과 프롬프트 캐시

- **날짜**: 2026-11-10
- **상태**: `experimental.stable_prompt_prefix` 구현, 제품 설정(`upstream/.croakcode/croakcode.jsonc`)에서 켬
- **측정 환경**: 운영 croak-gate, 모델 `qwen3.8-27b-nvfp4`

## 1. 증상

운영 게이트로 처음 보낸 "hi"의 첫 응답이 16.3초 걸렸다. 같은 세션의 두 번째 요청은 1.6초였다.

## 2. 원인

모델 서버는 캐시가 없으면 프롬프트를 초당 약 1,040토큰씩 처리한다. 첫 요청은 13,626토큰이었고, 첫 토큰까지 13.1초가 걸렸다. 같은 앞부분이 캐시에 있으면 같은 요청이 1.4초에 끝났다.

첫 요청이 커진 이유는 두 가지였다.

- Claude Code 스킬(`~/.claude/skills`) 9개가 시스템 프롬프트와 `skill` 도구 설명에 두 번 실렸다. 약 4,100토큰이다.
- 기본 `build` 에이전트의 시스템 프롬프트가 약 9,000자였다.

캐시가 자주 빗나가는 이유도 있었다. Qwen 채팅 템플릿은 시스템 프롬프트 뒤에 도구 정의를 붙인다. 시스템 프롬프트에는 날짜와 작업 폴더가 들어 있었다. 그래서 날짜가 바뀌면 그 뒤의 도구 정의 약 6,400토큰도 캐시에서 빗나갔다.

## 3. 조치

| 조치 | 위치 |
|---|---|
| 스킬을 모두 막았다(`permission.skill: "deny"`) | 사용자 설정 `~/.config/croakcode/croakcode.jsonc` |
| 짧은 `dev-main` 에이전트를 기본으로 두고 `build`를 숨겼다 | 사용자 설정 `~/.config/croakcode/agent/dev-main.md` |
| 환경 정보(모델, 작업 폴더, 날짜)를 첫 사용자 메시지로 보낸다 | 코드 `experimental.stable_prompt_prefix`, 제품 설정에서 켬 |

스킬을 일부만 허용하면 목록에는 남고 `skill` 도구는 빠졌다. 그래서 모두 막았다.

지침 파일(`AGENTS.md`, `~/.claude/CLAUDE.md`)은 시스템 프롬프트에 그대로 둔다. 게이트는 개인정보 허용 목록을 시스템 프롬프트에만 적용한다. 지침 파일을 사용자 메시지로 옮기면 그 안의 허용된 값이 가려질 수 있다.

## 4. 측정

이 저장소의 `AGENTS.md`(약 1,000토큰)를 뺀 값이다.

| 구성 | 프롬프트 | 캐시 없을 때 첫 토큰 | 캐시 있을 때 첫 토큰 |
|---|---|---|---|
| 조치 전 | 13,626토큰 | 13.2초 | 1.4초 |
| 스킬 차단 | 8,409토큰 | 8.0초 | 1.25초 |
| 스킬 차단과 `dev-main` | 6,955토큰 | 6.4초 | 측정하지 않음 |
| 예전 opencode 설정(비교용) | 7,637토큰 | 7.2초 | 1.45초 |

`stable_prompt_prefix`를 켜고 날짜만 바꾼 요청을 보냈다. 첫 토큰이 1.69초에 왔고, 6,144토큰이 캐시에서 나왔다. 옵션이 꺼져 있으면 날짜가 시스템 프롬프트 안에 있다. 그래서 날짜가 바뀐 요청은 도구 정의까지 캐시에서 빗나간다.

새 세션 두 개를 연달아 열었을 때, 실행 시간을 포함해 각각 약 4초였다. 프로세스 시작에 약 1.5초가 걸린다.

## 5. 남은 한계

- `AGENTS.md`가 다른 프로젝트의 첫 세션은 캐시에서 빗나간다.
- 서버 캐시가 밀려나면 다시 캐시 없이 처리한다.
- 캐시가 없을 때 첫 응답은 약 6~7초다. 도구 정의만 약 6,400토큰이다.

## 6. 측정 방법

가짜 OpenAI 호환 서버를 띄우고 `LITELLM_BASE_URL`을 그쪽으로 돌려 croakcode가 보내는 요청 본문을 받았다. 받은 본문을 게이트에 직접 보내 첫 토큰 시간과 `usage.prompt_tokens_details.cached_tokens`를 쟀다. 캐시 없는 경우는 시스템 프롬프트 맨 앞에 임의 문자열을 붙여 만들었다.

## 7. 도구 정의 지연 불러오기 (Phase 5 Task 8, 실험)

`experimental.deferred_tools`를 켜면 첫 요청에 기본 도구 여섯 개만 넣는다. 기본 도구는 read, edit, write, bash, glob, grep이다. 여기에 `tool_search`와 `tool_call`을 더한다. 나머지 도구는 `tool_search`로 정의를 받고 `tool_call`로 부른다.

| 항목 | 끔 | 켬 |
|---|---|---|
| 첫 요청 크기 (저장소 밖 폴더) | 26,715자 | 17,885자 |
| 도구 정의 크기 | 23,366자 | 14,536자 |

운영 게이트의 Qwen 27B로 작업 다섯 개를 끄고 켜서 돌렸다. 다섯 개 모두 두 경우에 성공했다.

| 작업 | 끔 | 켬 |
|---|---|---|
| todowrite로 할 일 세 개 | 성공 6초 | 성공 10초 (tool_call) |
| webfetch로 example.com 제목 | 성공 6초 | 성공 5초 (tool_call) |
| task로 하위 에이전트에 .txt 개수 세기 | 성공 21초 | 성공 18초 (tool_call, 답 3) |
| glob으로 파일 수 세기 (기본 도구) | 성공 10초 | 성공 11초 |
| read로 첫 단어 읽기 (기본 도구) | 성공 7초 | 성공 5초 |

Qwen은 `tool_search`를 부르지 않고, 그 설명에 실린 목록을 보고 `tool_call`을 바로 불렀다. 표본이 다섯 개라 기본값은 바꾸지 않았다.
