## 2. Phase 5 경로 시나리오

가짜 모델로 도구 호출 순서를 정해 실제 croakcode를 실행했다. 감사 기록은 `execution_audit` 테이블에서 읽었다.

| # | 시나리오 | 결과 |
|---|---|---|
| G1 | 거부한 도구(webfetch)를 `tool_call`로 부름 | 숨긴 도구 목록에 없고, 호출은 거부됨 |
| G2 | `tool_call`로 webfetch를 부름 | 감사 기록에 실제 이름 `webfetch`로 남음 |
| G3 | 실행 허가 필수, 공개키 없음, gate 모드 | 기본 도구와 `tool_call` 모두 `permit_no_key`로 거부되고 감사 기록에 남음 |
| G4 | 비밀 경로를 `tool_call`과 기본 도구로 읽음 | `hwp_read`, `read`는 막힘. `hwp_cli`는 막히지 않음 (아래 4절) |
| G5 | `tool_call`로 하위 에이전트(task) 실행 | 자식 Run이 부모 Run과 감사 기록에 연결됨 |
| G6 | 곁질문에 모델이 도구 호출(write, bash)을 돌려줌 | 파일이 생기지 않음. 막힌 이유가 우연이라 고침 (아래 4절) |

G4는 테스트 폴더 안에 가짜 `.ssh/id_rsa`와 `.env`를 만들어 시험했다. 실제 홈 폴더의 비밀 파일은 쓰지 않았다.

## 4. 찾은 문제와 조치

| 문제 | 원인 | 조치 |
|---|---|---|
| `hwp_cli`가 비밀 경로를 입력으로 받아 실행함 (G4) | 출력 경로만 검사하고 입력 인자는 검사하지 않았다. Phase 5 이전부터 있던 틈이다 | 옵션이 아닌 모든 인자를 비밀 경로 규칙으로 검사한다. 시험에서 거부됨을 확인했다 |
| 곁질문 요청의 도구에 실행 함수가 남아 있음 (G6) | `toolChoice: "none"`은 모델에 하는 요청일 뿐이다. 모델이 도구 호출을 보내면 실행될 수 있는 구조였다 | 곁질문 요청에서 도구의 실행 함수를 뺐다. 정의는 그대로라 캐시는 유지된다. write와 bash 모두 실행되지 않음을 다시 확인했다 |

두 조치는 같은 PR에 담았다.
